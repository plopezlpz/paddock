Keep an eye on your agents without leaving tmux.

Stay in tmux. Add a control panel for your agents.

Keep your tmux.conf, your prefix and keybindings, your plugins and sessions. paddock is one popup on top of them.

TPM

1 Add this to your tmux config:

~/.tmux.conf
set -g @plugin 'plopezlpz/paddock'
set -g @plugin 'plopezlpz/agent-status.tmux'   # agent state
set -g @agent-icon-in-status on                # its dot in front of each window name

2 Press prefix I to install the plugins, then prefix a. It offers to download paddock's binary from the GitHub release (checksum verified), then lists the agents it finds and offers to hook them up. Restart those agents, and press prefix a again to open paddock.

prefix a is the default key, unless your config already binds it; @paddock-key picks another. To update, press prefix U; the key then offers paddock's new version. Then run bash ~/.tmux/plugins/agent-status.tmux/manage-provider.sh install again so your agents get the current hook commands. No Rust needed.

Homebrew

1 Install paddock and agent-status.tmux:

shell
brew install plopezlpz/tap/paddock
git clone https://github.com/plopezlpz/agent-status.tmux ~/.tmux/plugins/agent-status.tmux

2 Add this to your tmux config, then reload it with tmux source-file ~/.tmux.conf:

~/.tmux.conf
set -g @agent-icon-in-status on                # agent state dot in front of each window name
run-shell 'paddock init'                       # prefix a opens paddock
run-shell 'bash ~/.tmux/plugins/agent-status.tmux/agent-status.tmux'

3 Hook up your agents, once, then restart them. It lists the supported agents it finds and asks first:

shell
bash ~/.tmux/plugins/agent-status.tmux/manage-provider.sh install

If tmux says 'paddock init' returned 127, its PATH lacks Homebrew's: write out the full path, /opt/homebrew/bin/paddock (Apple silicon), /usr/local/bin/paddock (Intel Mac) or /home/linuxbrew/.linuxbrew/bin/paddock (Linux). To update, brew upgrade, git -C ~/.tmux/plugins/agent-status.tmux pull and reload tmux, then run step 3 again so your agents get the current hook commands.

What it does.

A fast tmux popup for jumping between sessions, windows and panes, that also shows which AI coding agent is working, which is waiting for you and which has finished.

  1. Your tmux, unchanged, plus an agent state dot

    agent-status.tmux puts a dot in front of each window that has an agent (one addition to your window-status-format), coloured for working, finished or asking you something. You pick the colours with @agent-color-*; the theme shown here uses orange, blue and red.

    It works through agent hooks. Claude Code, Codex, pi, OpenCode and other agents with hooks report working, asking and finished; agent-status.tmux colours the window's dot, and paddock shows the same state.

  2. Open paddock to manage agents and tmux

    prefix a opens a popup over whatever you were doing. Tab shows every agent, with the one that needs you first, and Enter jumps to the pane that is asking. Start typing to filter sessions, windows and agents.

  3. Group agents by status, session or folder

    ctrl-g changes how the agents tab is grouped. Grouped by folder, agents working in the same project, one per worktree, sit together.

  4. Skim agents without jumping to them

    The selected pane, live, beside the list. Move down the list and the preview follows, so you can read what an agent is doing, or asking, before you jump to it.

    Shown when the popup is at least 102 columns wide. ctrl-o toggles it.

  5. Rename an agent, with a suggested title

    ctrl-r renames the selected agent in place. Press ctrl-r again and paddock fills in a suggested title; Enter saves it.

    agent-status.tmux asks pi for the suggestion, so pi must be installed.

  6. Sessions, windows and panes from the popup

    New, rename, move, kill and undo, without leaving the popup. Drag with the mouse, or right-click for a menu.

  7. Know when an agent needs you

    A red dot in the status bar means an agent is waiting for you; open paddock and it is the first card. agent-status.tmux can also raise a clickable desktop notification (with alerter, terminal-notifier or notify-send installed).

  8. On your phone

    Under 80 columns paddock switches to a compact two-line layout with tappable words. Tap the selected row to open it.

    With @paddock-click on, a click on the session name in the status line opens paddock. It needs set -g mouse on.

Agent state works through agent-status.tmux, paddock's companion plugin, which listens to your agents' hooks. All features and keys are in the README.

Comfortable in tmux? Don't start over.

herdr is an agent runtime: its own server that keeps your agents' terminals alive, with its own TUI, CLI and API. It's a good home if you're starting fresh. But if you already live in tmux, switching means a new session model and new keys, and setting aside the config, plugins and muscle memory you've built up. paddock takes the other route: one popup in the tmux you already run.

  • Your ~/.tmux.confUntouched, apart from a few lines to load paddock and agent-status.tmux.
  • Your prefix and keybindingspaddock adds one key, which you choose.
  • Your pluginsTPM and everything you run with it.
  • Your sessions, windows and scriptsThe tmux you already have.
  • sshWherever tmux runs, paddock does.
  • Your phoneA compact two-line layout under 80 columns.

paddock doesn't start or wrap your agents: they run in your panes as they do today, and agent-status.tmux picks up their state from their hooks.

agent-status.tmux

The agent side of paddock. It hooks into each agent you use and keeps its state on the agent's pane, where the status bar and paddock both read it.

  • pi
  • OMP (Oh My Pi)
  • OpenCode
  • Kimi Code
  • MastraCode
  • Kilo Code (partial: no exit event)
  • Claude Code
  • Codex (run with --no-daemon)

The install steps at the top set it up. @agent-icon-in-status on puts the dot in front of your window status formats (set yours before the plugins load). To place it yourself, leave it off and add this to your formats:

~/.tmux.conf
#{?@agent-icon,#{@agent-icon} ,}

It needs tmux 3.8, Bash 3.2 and jq; desktop notifications need alerter, terminal-notifier or notify-send, and suggested titles need pi. Codex runs a hook only once you trust it (it asks when it starts), and in tmux must run as codex --no-daemon: its default background server runs hooks without knowing their pane. Agents without lifecycle hooks, such as Gemini or Cursor, are not supported: their state can't be known without polling the pane.

Under the hood

The state lives in plain tmux pane options, so other tools can set them too (one agent per pane, one tool setting them per tmux server). Only @agent-state is required.

Pane optionValue
@agent-stateworking, asking or idle
@agent-unseen1 when an idle agent finished a turn you haven't looked at
@agent-stale1 when the state hasn't been confirmed recently (shown with a ?); paddock also shows a ? while a shell is the pane's foreground command, as after an agent killed without its exit hook, so a wrapper script or launch command should exec the agent, e.g. exec claude 2>/dev/null (bash runs a command with a redirection in a child)
@agent-kindthe agent's name, e.g. claude
@agent-auto-descriptionan automatic title, e.g. the first prompt
@agent-state-atwhen the state last changed, in Unix seconds
